# WSL 真 Linux 性能对比（2026-11-07）

与 `docs/perf-plan-2026-11-07.md`（MSYS2/Cygwin 基线）互补的独立平台校验。

## 方法

- **两侧同为 Linux ELF**：oracle `/usr/local/bin/bash`（GNU bash 5.3.0(1)-release，
  真 Linux），wash 为 WSL 内原生 `cargo build --release`（`/var/tmp/wash-build/target/release/wash`）。
  不再经 interop 跑 Windows `.exe`，文件系统/进程/环境视图完全一致。
- 命令：
  ```bash
  cd /var/tmp/wash-build && env -u BASH_ENV -u WSLENV \
    BASH_BIN=/usr/local/bin/bash ROUNDS=5 \
    bash tests/perf/bench.sh /var/tmp/wash-build/target/release/wash
  ```
  （清 `BASH_ENV`/`WSLENV` 避免宿主注入污染；`LC_ALL=C`、HOME 沙箱化由脚本保证。）
- 测量纪律：`tests/perf/bench.sh` 三合一，bash/wash 交错 best-of-N（N=5×3 轮 + N=9 一轮），
  同窗口比值；本机噪声极大，单轮绝对值不可用于下结论。

## 结果（四轮）

| workload | R1 (5) | R2 (5, 高噪声) | R3 (5) | R4 (9) | 跨轮最佳 |
|---|---|---|---|---|---|
| arith-loop(2000) | 0.71x | 0.63x | 0.80x | 0.56x | **0.56x** |
| builtin-echo(500) | 0.62x | 0.49x | 0.58x | 0.50x | **0.49x** |
| fork-exec-true(100) | 0.99x | 0.66x | 1.12x | 1.01x | **≈1.00x 持平** |
| cmdsub(100) | 0.79x | 0.56x | 0.79x | 0.80x | **0.56x** |
| subshell(100) | 0.78x | 0.80x | 0.69x | 0.75x | **0.69x** |
| pipeline(50) | 0.86x | 0.73x | 1.02x | 0.94x | **0.73x** |
| expand-heavy(1000) | 0.57x | 0.53x | 0.53x | 0.56x | **0.53x** |
| **TOTAL** | **0.85x** | 0.65x | 0.93x | **0.84x** | **0.84–0.85x** |
| **启动(50次)** | **0.44x** | 0.23x | 0.45x | **0.44x** | **0.44x** |
| **内存 VmRSS** | 1.00x | 0.99x | 1.00x | 0.98x | **≈0.98–1.00x** |

绝对值（最低噪声窗口 R1）：bash 单次启动 ~4.6ms、wash ~2.1ms；
VmRSS bash ~3184KB、wash ~3168KB。

## 与 MSYS2/Cygwin 基线对照

| 维度 | MSYS2（Cygwin, bash 5.3.20） | WSL（真 Linux, bash 5.3.0） | 解读 |
|---|---|---|---|
| 性能 TOTAL | 0.93x | **0.84–0.85x** | 真 Linux 进程创建便宜，wash 内部语义优势释放更充分 |
| 启动 | 0.72x | **0.44x** | **强验证「94% Cygwin 地板」结论**：地板消失后，进程内 4x 优势直接变成 2.3x 整体启动优势 |
| 内存 | 0.85x | **0.98–1.00x** | Cygwin 侧 wash 更省主要来自 bash 的 Cygwin runtime 开销；真 Linux 上两者持平 |

## 结论

1. **全指标仍 ≤1.00x**（性能 0.84x / 启动 0.44x / 内存 ≈1.00x），
   MSYS2 的「全指标 <1.00x」结论在真 Linux 上成立且启动优势更大。
2. **内部语义负载（arith/echo/expand/cmdsub/subshell）稳定 0.5–0.8x** ——
   这是 P0 系列优化（AST 借用、AttrRefs、Prepared 惰性 env、tokenize 缓存、
   cmdsub 解析缓存）带来的实打实收益，与平台无关。
3. **外部命令密集负载（fork-exec-true / pipeline）≈1.00x 持平**，
   噪声窗口会出现 1.12x / 1.02x：真 Linux 的 fork+exec 很便宜，bash 的成熟 C
   路径没有劣势；wash 的优势不在进程创建。此现象是平台真实特征，不掩盖。
4. 启动时间结论升级：MSYS2 上「P1 已到平台极限」的判断成立（94% 地板），
   但地板是 Cygwin 专属；真 Linux 上 wash 启动快 2.3x，无进一步优化需求。
5. 内存无回退：两侧均 ~3.1MB（真 Linux），无泄漏迹象。

## 注意事项

- WSL 宿主共享 CPU，四轮绝对值最大波动 4.5x（TOTAL 429ms ↔ 1949ms）；
  **只看同窗口比值 + 跨轮最小**，别用单轮读数。
- 必须 release 对 release（debug 版 Rust 无优化，比值不可比）。
- WSL ext4 偶发 emergency read-only、`/tmp` 被实例回收清空，构建目录放 `/var/tmp`。
